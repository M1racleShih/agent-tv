AgentTV：看见进展，随时记录想法

你同时推进多个项目，需要一处查看各个 agent 的进展和待处理结果，也需要一处随时写下、整理和找回 idea、TODO 与 prompt。Preview 和 Record 是并列的两个核心功能。

自研方向已确认 核心使用方式已确认 GUI 以你的 demo 为参考 技术方案待确认

本文区分已确认需求、设计建议和待验证能力。GUI 以你提供的 demo 为主要参考；本次补充 workspace 优先归属与本机接入结果。具体技术选择、数据行为和验收目标见 接入与数据设计。产品开发安排在整体方案确认之后。

02 两个并列的核心功能

Preview：知道工作推进到了哪里

按项目查看活跃会话、执行状态和最新消息。某个会话需要你回复或已经给出结果时，保留待处理标记，从顶部入口可以找到。

以后可以按项目、agent、任务名称和会话内容检索，打开原来的工作记录，继续处理或复盘。

Record：随时记下并管理想法

有想法时马上写下来；一条记录可以是几句话、TODO 清单或长 prompt。写作时可以暂时不选择项目，也不选择 agent。

以后再编辑、搜索、分类、归档，或整理成待发送 prompt。记录本身有价值，可以长期保留。

建议首版把 Record 做到这些程度

  • 入口随时可见。顶部始终提供“快速记录”；切换到 Record 后使用完整工作台，集中整理全部记录。
  • 写完能找回来。自动保存，明确显示保存状态；刷新页面、重启服务后保留已保存内容。
  • 形式自由。正文支持 Markdown 文本与 TODO 清单；标题可选，可从第一行生成默认名称。
  • 管理方便。支持编辑、搜索、项目筛选和归档；标签建议作为轻量的可选分类方式。
  • 随时可以准备下一步。记录可关联项目、agent 类型或具体会话，也可以保持未关联。
  • 发送过程可控。整理好的记录可以标为“就绪待发”，复制后仍保留。确认粘贴并发送之后，由你标记已发送，可选择关联会话跟踪结果。

Record 的验收需要单独进行：即使一个 agent 都没有启动，你也能完成记录、修改、查找、整理与恢复已保存内容。

03 按你的 demo 组织工作区

主要 GUI 参考为 /home/shq/opensource/agents/AgentTV/index.html。你已明确，这是一份表达期望样子的 GUI demo，具体界面和交互细节在实际开发时完善。本节记录它的布局、使用流程和视觉方向。

顶层采用两个并列工作区：Preview 监控、Record 工作台。两者共用左侧项目栏、顶部搜索与快速记录入口。等待输入、待 Review 和 Ready 作为顶部的数量提示与快捷入口。

Preview：项目分组的监控墙与任务索引

Preview 内部切换“Live 监控墙”和“Task 索引与复盘”。Live 按项目分组排列 agent 卡片，便于扫视多个并行任务。卡片呈现 agent、模型、宿主、任务名称、状态与最新消息；需要处理的结果保持醒目。

Task 索引以表格检索已发现的会话，包括运行中、结束和归档的历史。点击卡片或索引行，从右侧打开详情抽屉，查看原始 prompt、会话内容、产出与已有的文件变更信息，关闭后继续处理原来的项目。顶部全局搜索用于任务、agent 与输出关键字检索。

界面区域采用的布局与用途
顶部全局栏Preview / Record 切换、搜索、快速记录，以及 Running、等待输入、待 Review、Ready 数量。点击相应入口查看需要处理的内容。
共享项目栏建议默认导入 herdr workspace 作为项目分组，显示已关联目录与关注事项数量；保留创建项目、关联目录的能力。切换工作区时保留选择。
Live 监控墙按项目分组的卡片网格，结合 agent 筛选与状态筛选。卡片展示最新消息和产出入口，具体密度随可用宽度调整。
Task 索引与复盘Preview 内的表格视图，展示任务名称、项目、agent、模型与时间信息，支持检索和打开详情。
详情抽屉从右侧打开，查看会话与结果；可基于结果创建一条 Record，保留源会话关联。
快速记录在任一主工作区从顶部打开轻量输入窗口；项目可选，填写想法后保存到 Record。

Record：完整的写作与整理工作台

进入 Record 后，左侧项目栏继续保留；中间是记录列表，右侧是完整编辑工作台。记录列表支持阶段与内容搜索，编辑区呈现标题、可选项目、来源关联、正文和 Markdown 预览。常用操作随当前记录阶段显示。

阶段名称参考 demo：灵感记录 → 整理成熟 → 就绪待发 → 派发执行 → 归档复盘。idea 与 TODO 可以长期保留，也可以反复整理、回退或直接归档。记录是否交给 agent 执行由你决定。

Record 详细设计说明各阶段和发送记录。“派发执行”沿用已有发送约定：手动复制到原工具，确认实际发送后记录状态；会话关联用于跟踪结果。demo 展示的一键投递能力在后续讨论中另定。

两个工作区怎样配合

  1. 1 · 观察扫视项目监控墙查看任务状态与最新消息，从顶部找到等待输入和待 Review 的会话。
  2. 2 · 记录随时捕捉新想法顶部快速记录，之后在 Record 中继续写作和整理，项目关联可选。
  3. 3 · 跟进从结果继续准备下一步在详情抽屉查看结果，基于结果创建关联 Record，明确确认已处理事项。
  4. 4 · 使用将成熟内容交给 agent在 Record 中复制 prompt，回到原工具发送，需要时关联执行会话。

视觉方向采用 demo 的表达

GUI 采用近黑背景、深蓝面板、清楚的卡片边界与蓝色操作强调。项目使用小范围的色点区分，agent 使用统一的中性徽章，运行、等待输入、待 Review 与异常由状态色表达。界面以便于扫视任务的紧凑布局为主，Record 为连续写作提供空间。

demo 中的展示信息怎样对应真实功能

布局与使用流程作为主要参考。数据与操作仍按已确认需求设计，以下细节在实际接入和开发时落实。

  • 进度百分比。实际版本依据上游真实进度显示；有活动记录而缺少可计算进度时，展示最新进展、运行时长和观察时间。
  • 模拟 Kill。demo 用它演示 agent 退出后卡片移除。首版继续观察原工具中的进程退出，历史与已有待处理事项保留。
  • 一键派发。demo 用它表达记录与接收会话的关系。首版发送方式沿用手动复制与确认，后续可单独讨论直接投递。
  • 待 Review。实际版本保存人的处理状态；查看或关闭抽屉后，提示继续保留。已退出的会话仍能从顶部关注入口与 Task 索引找到。
  • 摘要与变更。以已采集内容提供最新消息、产出和文件信息，完整会话可以展开。摘要生成方式和可提供的数据在接入验证后确定。
  • 数据恢复。Record、历史和待处理事项按本机持久保存设计；真实版本的保存状态与恢复能力需要独立验证。

04 状态、项目与检索怎样工作

执行状态与人的处理状态分别保存

agent 的一轮执行可能已经结束，而你还没处理结果。看板显示会话当前在做什么，同时保留需要你处理的事项。

发生的情况建议的显示与保存行为
正在执行显示在 Live 监控墙，展示最新进展与观察时间。长时间没有输出时继续依据执行信号判断状态。
等待回复、授权或处理错误会话保持可见，并生成待处理事项。首版由你在原工具里回复或授权。
本轮完成，agent 仍然存活会话显示为等待下一步或空闲，本轮结果进入待处理。这里的“完成”描述本轮执行。
你点开预览记录已查看，待处理事项继续保留。
你确认已处理或归档清除相应待处理标记，保留处理记录和会话历史。后续新一轮结果可以再次产生待处理事项。
agent 被 kill 或正常退出从 Live 监控墙移除，历史和已有待处理事项保留。执行中退出时，建议额外标记“执行中断”，供你检查。
采集连接断开或身份无法确认显示“状态待确认”或“采集连接断开”，保留最后观察时间。这种情况需要与已确认退出分别处理。

待处理事项建议按会话聚合，并保留对应执行轮次。多次事件可以合并成一个会话入口；下一轮开始后，上轮尚未确认的结果继续保留。

Record 的状态服务于整理

Record 的阶段表达参考 demo 的“灵感记录、整理成熟、就绪待发、派发执行、归档复盘”。这些阶段帮助你寻找和整理内容；idea 与 TODO 可以长期保存、回退或直接归档。复制后保留正文与当前阶段；你确认实际发送后，再记录发送状态、当时的正文和可选会话关联。关联会话的完成结果提供提示，Record 后续阶段由你选择。

默认沿用 herdr workspace，外部会话匹配明确目录

按你提出的方向，建议首版采用一个 herdr workspace 对应一个项目，左栏沿用已有名称和分组。Herdr 内的会话直接使用 workspace 归属。Codex desktop 和独立 CLI 使用你关联的目录匹配项目；目录重叠时选择更具体的路径，同一路径对应多个项目时先保留在“未分类”。你可以手动调整会话归属。

本机运行服务的 workspace 快照有名称和 ID，样本未提供统一目录，因此目录需要明确关联。AgentTV 保存自己的项目 ID 和 herdr 关联，workspace 关闭或重命名后，历史与 Record 仍可找到。身份和重连规则见 workspace 归属设计。

Record 可选择项目，也可留在全局收件箱。关联项目、会话的操作在 AgentTV 中保存，原始会话文件保持只读。后续仍可创建仅在 AgentTV 中使用的项目，承载代码、文档或团队工作。

以会话身份检索，名称可以调整

建议使用 agent 类型、来源数据目录和原生会话 ID 识别同一会话；herdr 和原生文件读取到同一会话时合并展示。Codex CLI 与 desktop 的同一原生会话合并，启动工具作为来源保存。会话名称使用原生标题，缺少标题时使用首条用户消息的预览，你可以在 AgentTV 中设置别名。

会话检索覆盖名称、正文、项目、agent 与时间。Record 检索覆盖标题、正文、项目和状态。中文片段检索需要纳入实际验证。

05 自研怎样接入现有工具

建议由 Rust + Tokio / Axum 负责采集和本地 HTTP 服务，SQLite 保存会话索引、待处理事项与 Record，Svelte + TypeScript 网页负责查看和编辑，SSE 推送状态变化。关闭浏览器时，采集服务继续保存进展。选择原因和数据恢复方式见 接入与数据设计，技术方案等待整体确认。

先复用可靠的信号，再补充各 agent 的观察方式

来源建议接入方式仍需验证
herdr 中的会话已读取运行服务的 session.snapshot，获取 workspace、当前 agent 与原生会话关联；后续用 events.subscribe 接收变化。CLI 是 0.9.4，运行服务是 0.9.1。事件订阅、断线重连、退出与缺少完成序号时的补充方式仍需验证。
herdr 外的 CLI读取原生会话文件，使用轻量 hook、pi 扩展或启动包装报告会话身份和执行事件；进程检查补充突然退出的判断。如何把每个执行实例准确关联到会话，如何处理切换会话、强制退出和 PID 重用。
pi原生扩展提供会话与 agent 生命周期事件；历史使用 JSONL 会话记录。具体事件按安装版本确认。自动重试、排队续写或压缩期间，哪个事件表示这一轮工作确实结束。
Kimi Code当前安装版本为 2.1.1。官方资料说明 state.json、session_index.jsonl 与 agents/*/wire.jsonl 保存元数据及事件。新旧会话格式差异、等待授权与执行结束事件的准确含义。首选读取已有记录与 hook 信号。
Codex CLI读取会话记录，并核查当前版本的生命周期 hook 或可观察执行信号；与 herdr 来源合并。同目录并发会话的准确关联，以及完成、等待授权、报错和强制退出的区别。
Codex desktop本项目原生记录已有开始、完成和中断事件，含 turn ID；写入锁能关联到持有会话的 Codex 进程。公共 app-server 可读历史，当前会话在其中为 notLoaded。优先验证项：原生事件与写入锁结合后的多会话状态、等待输入与授权、强制退出和观察延迟。
Claude Code结合原生会话 JSONL、官方 hook 或现有 herdr 集成，获得执行与等待输入信号。授权请求、普通回复和后台工作如何区分；异常退出是否留下足够的状态记录。

Herdr 的状态也有不同来源。已安装的 pi 扩展包含生命周期观察；Claude Code 与 Codex 集成中的脚本主要报告会话身份，状态仍可能依据终端文本判断。AgentTV 保存状态来源，并用原生事件验证完成与等待输入的含义。0.9.4 schema 中的 completion_seq 在当前 0.9.1 服务样本中未提供，设计按可选字段处理。

Herdr 接口依据 0.9.1 socket 文档与运行服务快照；Codex 接口依据 官方 app-server 文档与本项目原生样本；Kimi 存储依据 官方会话资料。检查结果及其范围见 本机验证记录。

“文件最近更新”只能证明最近有内容写入。kill 后及时移除，需要会话身份与存活信号；Codex desktop 的状态需要对应实际执行该会话的实例。新启动一个独立 app-server 的状态不能直接代表现有桌面实例。

数据保存与恢复

建议分别保存项目、会话、会话消息、执行观察、待处理事项与 Record。会话历史与实时观察相互关联；Record 可独立存在，可选择关联其中的项目或会话。

服务重启后恢复 Record、待处理事项与会话索引，再重新确认活跃会话。历史索引保存已读取的文本和来源位置；图片与较大的工具输出可以按需读取。原始文件已移除且内容未被保存时，详情页说明哪些内容已不可用。

Record 保存成功后才显示“已保存”。保存失败时保留编辑内容并显示失败状态，供你重试或复制。数据导出和归档可作为首版管理能力的一部分，具体格式在详细设计时确认。

07 首版需要通过的使用场景

以下为建议的验收场景，供我们在开发前确认。它们同时覆盖 Preview 与 Record。状态更新延迟和搜索规模在接入样本验证后确定。

场景可观察的结果
所有 agent 都没有启动仍可新建 idea、编辑 TODO、查找旧记录、管理分类与归档。
等待 agent 返回时想到新需求从顶部“快速记录”写下；可以暂不选项目和 agent，随后在 Record 工作台找回。
已保存一条长记录，刷新或重启服务正文、项目关联与状态保留；保存状态反映真实的持久保存结果。
寻找之前用中文写下的一个想法按标题或正文中的中文片段找到记录；会话历史也使用中文片段检索验证。
把一条记录整理为 prompt 并复制内容和换行保持正确；复制后保留记录，发送标记由你确认。
多个项目使用不同 agent 并行工作五个接入对象均有对应的活跃会话入口，可按项目查看、预览最新进展。
两个 herdr workspace 共用目录内部会话按实际 workspace 分组；外部会话无法唯一匹配时保留在未分类，可手动归属。
workspace 关闭或重命名历史任务、未处理事项和 Record 继续可查，项目名称改变后仍能找到原来的记录。
关闭 herdr 客户端，但 agent 继续运行看板继续展示其活跃会话；客户端关闭与 agent 退出分别判断。
在终端 kill 掉一个 agent对应会话从 Live 监控墙移除，历史可搜索；已有待处理结果保留。
agent 长时间执行，暂时没有新输出依据执行与存活信号保留正确状态，能够显示最后观察时间。
查看一条已完成会话后转去处理其他事情待处理入口仍保留；你明确确认后才清除。
Codex desktop 同时执行多个会话逐会话显示状态；结束其中一条时，其他会话继续正确展示。
同目录并发、切换会话、采集重启会话身份清楚，合并重复来源；Record、历史和待处理事项继续保留。

08 下一步需要确认什么

需求方向已经明确：自研、Ubuntu 单机、本机网页、旁路观察；Preview 与 Record 并列。你可以随时记录想法，随后再决定如何整理、关联和使用。
