用途与取舍

harness 是帮助后续 agent 理解项目、执行检查和继续工作的资料与工具，不是独立产品。当前保留一个 Python 标准库脚本、机器可读策略和关键场景目录，不再增加第二套执行入口。

新增规则或工具应解决实际开发中反复出现的问题。暂未实现的能力写明缺失，不靠增加文档或空工程表示进度。

资料放在哪里

  • README：项目是什么、当前状态和上手命令。
  • AGENTS.md：必要开发规则；CLAUDE.md 只导入这一份。
  • 需求与架构设计：产品行为与技术决定。
  • 执行计划：当前进度、决定和剩余工作；启动记录保留历史验收，不作为日常必读。
  • policy.json：文档清单、忽略目录和依赖方向；cases.json：关键场景、设计出处和自动命令。

只读当前任务相关内容。细节在负责它的文件中维护，其他入口用链接引用，不重复抄写状态与规则。

何时需要计划

小修复、文档和样式调整在会话中说明目标与检查即可，不新建计划文件。涉及多模块行为、数据迁移或较大接入工作时，更新已有 HTML 计划；没有适用计划再使用模板创建。

计划记录影响后续工作的进度、决定、验证和遗留问题，不逐条复制终端日志。设计只随行为变化更新；场景目录只追踪关键验收场景，不要求每个测试单独登记。

检查命令

在项目根目录运行 python3 scripts/harness.py <命令>，要求 Python 3.11 或更高版本。

命令范围
doctor首次进入环境或工具链变更时使用。检查 Python、Git、Rust、Node、npm 和 dskills，不安装工具、不修改配置。
check --scope docsHTML 标签嵌套、链接与锚点、计划状态和必需章节、共享指令入口、忽略规则、场景目录。
check --scope harness文档检查加 harness 自测。
check以上检查，加已存在的 Rust 和网页工程检查。缺失的产品工程标记 NOT_APPLICABLE。
cases列出关键场景。planned 表示待实现；registered 仅表示已登记命令，不表示测试通过。
check --scope product首版交付前运行。要求完整产品工程、可复现配置和全部关键场景命令，并逐项执行；缺失时失败。

结果为 PASSED、FAILED 或 NOT_APPLICABLE；出现失败时返回非零退出码。普通检查可以在产品未创建时通过，严格产品检查此时应失败。

Rust 工程存在时执行 Cargo 元数据依赖检查、cargo fmt --all -- --check、cargo clippy --locked --workspace --all-targets -- -D warnings 和 cargo test --locked --workspace --all-targets。

网页工程存在时执行 npm 的 check、test -- --run 和 build scripts，均须非交互运行。严格产品检查还要求 Cargo.lock、rust-toolchain.toml、web/package-lock.json 和 web/.node-version。

检查器不会安装产品依赖。仓库托管于 GitHub；CI 尚未配置，未来接入时沿用同一检查入口。

架构检查

当前采用四个 Rust 包与网页目录，按产品实现需要逐步创建。具体允许的依赖见 policy.json：domain 不依赖其他本地包，storage 和 adapters 可依赖 domain，server 可依赖三者。

执行器读取 Cargo 元数据，检查 workspace 包位置、本地依赖方向，以及 domain 对 Axum、Tokio、rusqlite 的禁止依赖。这是静态包关系检查，不证明业务正确，也不全面限制所有第三方依赖。

结构需要调整时，随实现一起修改架构设计、policy 和相关测试，不为满足旧目录约定保留空模块。

测试与实际使用分别验证

日常自动检查

使用合成来源和可丢弃数据，不读取真实 agent 历史，不修改用户配置，也不启动或终止已有 agent。进程测试只清理本次创建的进程。harness 自测覆盖文档错误、依赖违规、命令失败、空测试运行和技能配置等失败路径。

子命令获得独立的 AGENTTV_DATA_DIR，以及 AGENTTV_SOURCE_MODE=fixture、指向 tests/fixtures 的 AGENTTV_FIXTURES_DIR。这些环境变量不是操作系统沙箱，产品和测试必须实际遵守。

14 个关键场景覆盖 workspace、Preview、待处理、Record、搜索和安全渲染。实现相应行为时登记能实际执行目标测试的命令，避免只检查命令是否成功退出。

真实接入与页面

真实来源单独验证，记录具体版本、操作范围和未覆盖行为。herdr CLI、运行服务与 desktop 内置版本分别记录；原生历史保持只读，已有会话不受影响。

页面按用户 demo 方向，用合成内容启动独立实例，实际操作 Preview / Record、保存、复制、搜索和确认，检查窄屏与长文本。浏览器工具可用时做交互和视觉检查；不可用时报告未验证部分，不用类型检查代替实际使用结论。

严格产品检查只证明所运行的自动检查结果。五个来源的生命周期准确性与 GUI 观感仍需实际观察。

结果保存

doctor 和 check 在 .harness/runs/<UTC 时间与唯一标识>/ 保存 JSON 报告；子命令另有日志和独立数据目录。报告包含范围、实际命令、时长、结果及场景登记数量。cases 只输出登记情况。

运行记录留在本机，不进 Git。交付说明给出实际检查结果和未覆盖部分；已有计划只保存后续需要的短结论、重要失败的复现方法和报告路径，不另建验收文档。真实会话正文和凭据不复制进仓库。

维护原则

先推进产品。只有现有流程造成重复问题时，才补检查、规则或工具；不为完整性增加模板、登记项和固定步骤。

技能由 dskills 以 no-track 管理，当前只选 plain-docs。Codex、Kimi、pi 共用 .agents/skills，Claude 使用 .claude/skills。技能、运行记录和构建产物保持 Git 忽略。

不增加定时维护、子 agent 或远程自动化的默认授权，范围与审批要求见 AGENTS.md。
