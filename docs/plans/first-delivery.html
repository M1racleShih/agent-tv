01 目标与范围

用户在 Ubuntu 本机网页随时写 idea、TODO 和 prompt，保存后能找回；同时按 herdr workspace 查看会话、最新进展与待处理结果。发送继续使用手动复制粘贴，GUI 采用用户 demo 的 Preview / Record 主工作区和共享项目栏。

相关设计见 workspace 归属、会话与状态、Record 流程和GUI 方向。当前已有设计文档与开发 harness，产品源码、测试样例和运行入口等待本计划开始后创建。

02 按可验证的结果推进

步骤与状态要完成的工作与可观察结果
1 · 待开始
建立接入样例		在 tests/fixtures 创建带格式来源说明的合成记录。按需要建立 domain 和 adapters，提供可运行的重放入口，验证 workspace、轮次与实例身份。实际安装版本使用独立测试会话核查，尤其是 desktop 的等待、并发和退出。
2 · 待开始
提供独立 Record		建立 storage、server 与 web。实现快速记录、编辑、自动保存、中文搜索、归档、Ready 与复制；已保存内容在刷新和重启后恢复。所有 agent 停止时仍可使用。
3 · 待开始
连接最小 Preview		读取 herdr workspace 和原生会话，提供 Live 卡片、Task 索引和详情。执行观察、人的确认与历史分别保存；查看结果后仍能找到待处理入口。
4 · 待开始
补齐来源与恢复		完成 pi、Codex CLI、desktop、Kimi、Claude 的适配，验证重复事件、断线、会话恢复与实例退出，逐项更新场景命令。
5 · 待开始
检查实际使用		用真实长度的合成内容完善 GUI，实际操作保存、复制、搜索和确认流程。记录真实接入、页面观察、自动检查结果和仍有的限制。

创建各包时采用 harness 的 Rust 分层，同时保存依赖锁文件和工具链版本。较大步骤可拆成独立计划，保持本页进度反映整体可用结果。

03 已知事实与当前决定

2026-10-14 · 归属：首版默认一个 herdr workspace 对应一个 AgentTV 项目。外部会话匹配明确关联的目录，歧义保留未分类；Record 保留全局收件箱。

2026-10-14 · 实现：采用 Rust / Tokio / Axum、SQLite 与 Svelte / TypeScript。本机数据独立保存，服务可以在浏览器关闭后继续采集。

2026-10-14 · 来源：本机 herdr CLI 和正在运行的服务版本不同；desktop 公共 app-server 可读历史，实际执行需要研究原生轮次与锁信息。现有样本见 本机观察，尚未完成全部生命周期实测。

2026-10-14 · 验证：普通检查使用合成来源和临时数据，真实接入独立验证。影响需求覆盖的能力缺口带具体观察回到方案讨论。

04 以场景验证每一步

开发前运行 python3 scripts/harness.py doctor；每步实现后按影响运行 python3 scripts/harness.py check。对照 关键场景目录，补充能实际失败和通过的自动命令。

接入先覆盖 workspace-01/02、preview-01/02/03 和 attention-01/02；Record 覆盖 record-01/02/03/04；历史、中文检索和安全渲染覆盖 search-01/02 与 rendering-01。当前这些产品场景均未登记自动命令。

产品工程提供可指定数据目录、来源模式和监听端口的启动方式，成功后输出实际访问地址。网页使用该实例执行界面检查。具体产品命令与接口在实现后写回此处；当前可执行入口仅为 harness。

整个首版交付前运行 python3 scripts/harness.py check --scope product，并列出五个来源的实际生命周期结果和页面使用记录。当前运行严格产品检查应返回失败，说明产品工程和场景测试仍未创建。

05 使用独立数据，重跑保留来源

样例使用合成 ID 与正文，原生真实记录保持只读。开发和测试的数据目录明确指定为本项目临时目录；测试清理仅涉及本次创建的数据和进程。

导入程序保存读取位置和来源身份，重跑时去重。数据库格式变化使用迁移与一致性备份；失败保留诊断信息和已保存的 Record。首次真实接入前检查只读来源和临时写入目录是否实际生效。

代理或连接失败按当前用户环境处理，保留具体错误。采集连接断开时页面显示最后观察与待确认状态，恢复后重取快照。
